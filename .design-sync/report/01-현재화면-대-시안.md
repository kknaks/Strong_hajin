# 01 — 현재 화면(B) → 확정 시안(A) 로 가려면 무엇을 바꾸나

- **A 확정 시안**: `.design-sync/screens/` (2026-09-17 내려받음, 12파일)
- **B 현재 화면**: `frontend/src/features/work/` · `frontend/src/shell/` · `frontend/src/ds/`
- **원칙**: 시안이 정본이다. 아래는 「시안에 있는데 코드에 없거나 다른 것」만 적는다. 우선순위·공수는 적지 않는다.

> **읽는 사람에게** — 현재 코드는 이미 *이전 판* 핸드오프를 상당 부분 흡수한 상태다(코드 주석의 「바퀴 5a/5b/5c」).
> 그래서 아래 목록은 「처음부터 다시」가 아니라 **아직 안 맞는 자리**만이다. 코드가 시안과 다르게 간 자리는
> 대부분 소스에 그 이유가 주석으로 남아 있어서, 항목마다 그 주석을 같이 인용했다 — 뒤집으려면 그 근거부터 봐야 한다.

## 1. 탭 — 세 갈래의 이름과 뜻이 다르다 ★가장 큰 차이

| | 시안 | 현재 코드 |
|---|---|---|
| 탭 값 | `my` · `sent` · `done` | `mine` · `sent` · `organization` |
| 탭 이름 | 내 업무 / **보낸 업무** / **완료 업무** | 내 업무 / **요청·배정** / **조직 업무** |
| 근거 | `handoff/my-work/js/data.js:52-56` | `frontend/src/features/work/MyWorkPage.tsx:429-440` |

- 시안의 **「완료 업무」 탭이 코드에 없다.** 코드는 이것을 상태 필터로 처리하며, 그 판단이 주석에 있다:
  `MyWorkPage.tsx:427` — 「시안의 「완료 업무」 탭은 우리가 상태 필터로 하는 일이라 탭을 새로 만들지 않았다.」
- 코드의 **「조직 업무」 탭이 시안에 없다.** 시안 3탭 안에 대응하는 자리가 없다 (`data.js:52-56`).
- 코드의 **「요청·배정」** 은 받은·보낸·참조 셋을 한 탭에 담는다(`MyWorkPage.tsx:499-577`). 시안의 「보낸 업무」는
  **내가 남에게 보낸 것 한 갈래**뿐이다(`work-data.js` 의 `group: 'sent'` 4행 — 전부 내가 보낸 것).
  코드 주석이 이 불일치를 이미 적어 뒀다: `MyWorkPage.tsx:426` — 「「요청·배정」은 받은·보낸·참조를 함께 담는 우리 탭이라 시안의 「보낸 업무」로 부르면 틀린다.」

**바꿔야 하는 것**: 탭 3종의 값·이름·담는 내용. 「받은 요청」과 「참조된 업무」가 시안 어디로 가는지가 정해지지 않았다 → **OQ-01**.

## 2. 본문 표 — 세 개의 표가 필요하다

### 2.1 「내 업무」 표 — 별표 열 (6열 vs 5열)

- 시안: 6열 = **별표** · 제목/종류 · 요청자 · 기한 · 상태 · 액션 (`handoff/my-work/js/my-work.v2.jsx:99-151`, 별표는 `:115`)
  격자도 6열로 못박혀 있다: `handoff/my-work/css/components.css` 의
  `.scax-task-table__head,.scax-task-table__row{grid-template-columns:44px minmax(0,1fr) 120px 140px 120px 200px}`
- 현재: 5열, 별표 없음 — `MyWorkPage.tsx:604-610`, 클래스도 `scax-task-table--nostar` (`MyWorkPage.tsx:593`)
- 코드가 그렇게 한 이유가 소스에 있다: `MyWorkPage.tsx:598-601` — 「`starred` 필드도 저장 엔드포인트도 없어서 눌러도 아무 데도 안 남는다 … 필드가 생기면 modifier 를 떼고 DS 기본 6열로 돌아간다.」
- 시안은 `starred` 를 데이터로 들고 있다: `work-data.js` 의 `w6` 에 `starred: true`, 토글 핸들러도 있다(`my-work.v2.jsx:386`).

**바꿔야 하는 것**: 별표 열 부활 + `starred` 계약(필드·저장 경로). BE 계약이 없다 → **OQ-02**.

### 2.2 「보낸 업무」 표 — 시안에만 있는 모양

- 시안 `SentTaskTable` (`my-work.v2.jsx:154-191`): 5열 = 제목 · **담당자** · 기한 · **상태(읽기 전용 배지)** · 액션(**「다시 요청」 단추 하나**, `:184`)
  격자는 24px 선두열: `components.css` 의 `.scax-task-table--sent … {grid-template-columns:24px …}`
- 현재: 이 모양의 표가 **없다.** 대신 `RequestRelationSection` 3벌 + `sentAssignments` 표 (`MyWorkPage.tsx:499-577`, `:525-567`),
  열은 업무명 · 상태 · 보낸사람/담당자 · 액션(「상세보기」) 이고 `DataTable`(시맨틱 `<table>`) 을 쓴다.
- 「다시 요청」이라는 커맨드가 현재 화면에 없다. 가장 가까운 것은 상세 드로어의 재상신(`MyWorkPage.tsx:512` 힌트 「조정 요청을 받으면 상세에서 내용을 고쳐 재상신합니다」).

**바꿔야 하는 것**: `SentTaskTable` 신설(div+grid), 「다시 요청」 목록 내 커맨드, 상태를 Select 가 아닌 배지로.

### 2.3 「완료 업무」 표 — 시안에만 있는 모양

- 시안 `DoneTaskTable` (`my-work.v2.jsx:194-232`): **그룹 두 벌**(「내 업무」 / 「보낸 업무」, `data.js:129-132`)이
  접이식 머리(`.scax-task-table__group`)로 나뉘고, 열은 제목 · **상대** · **처리일** · 상태 · 액션(빈칸).
  상태 배지는 `DONE_STATUS = { done: 완료/info, cancelled: 취소/danger }` (`data.js:134`).
- 현재: 없다. 완료·취소는 「내 업무」 탭의 상태 필터로만 본다(`frontend/src/lib/labels.ts:188`).
- 배지 `tone: 'info'` 는 우리도 가지고 있다(`frontend/src/ds/Badge.tsx:24` · `frontend/src/styles/components.css:198`) — 차이 아님.

## 3. 칩 바(필터) — 축이 다르다

| | 시안 | 현재 코드 |
|---|---|---|
| 내 업무 | 전체 / **받은 요청** / 막힘 / **기한 지남** (`data.js:58-63`) | active / all / open / in_progress / blocked / done / cancelled (`frontend/src/lib/labels.ts:188`) |

| 완료 업무 | 전체 / **확인 대기** (`data.js:119-122`) | 없음 |

- 시안의 칩은 **라벨에 건수를 달고 있다** — 「전체 (00)」 「막힘 (0)」. 현재 코드의 칩에는 건수가 없다(`MyWorkPage.tsx:448-451`).

- 현재 코드에는 시안에 없는 것이 하나 더 붙어 있다 — 칩 바 오른쪽 끝의 **보기 방식(목록/칸반/타임라인) SegmentedControl** (`MyWorkPage.tsx:454-461`).
  주석: `MyWorkPage.tsx:453` — 「시안에 자리가 없다는 이유로 보기 방식을 없애지 않는다. 시안의 오른쪽 끝 자리에 둔다」.
